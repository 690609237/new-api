# 20260808 订阅套餐与额度邮件通知更新日志

## 更新目标

在不改变用户唯一账号分组的前提下，让用户可同时购买多个订阅套餐，并在创建 API Key 时选择各套餐对应的倍率分组。套餐额度耗尽、到期或被管理员终止后，相关 API Key 自动回退到用户账号分组，并按回退后的倍率使用钱包余额。

## 功能与设计

### 订阅套餐

- 套餐增加“订阅权益分组”，与旧的“升级用户分组”模式互斥；新模式不修改用户账号分组，旧套餐保持原逻辑。
- `GET /api/token/groups` 合并返回用户普通可用分组和当前有效的订阅分组；无有效订阅时不暴露订阅倍率。
- 用户同时持有多个有效套餐时，接口返回每个套餐的权益分组和对应倍率，不再只保留最近购买套餐的分组。
- API Key 记录所绑定的订阅分组，创建和编辑时校验用户是否具有对应的有效套餐；`auto` 分组不能绑定订阅权益。
- 同一权益分组可购买多次，计费按到期时间顺序消耗，多份套餐额度聚合；只有该分组全部可用额度耗尽后才回退 API Key。
- 套餐绑定期间只扣对应订阅额度，禁止以订阅折扣倍率直接扣钱包。回退后按用户账号分组倍率扣钱包，套餐剩余额度不返还。
- 套餐额度耗尽、到期、删除或管理员终止时，将相关 API Key 的 `group` 改回用户账号分组并清空订阅绑定，同时失效 Token 缓存。
- 套餐的 `enabled` 只表示是否允许继续销售。管理员禁用套餐时，会在同一事务内终止当时已有的有效订阅，并将相关 API Key 回退到用户仍持有的其他有效订阅分组或账号分组；重新启用套餐不会恢复已终止订阅。
- 禁用套餐前已经创建的待支付订单，在支付回调成功后仍按下单时的套餐正常履约；管理员不能手动为用户绑定已禁用套餐。
- 兼容旧式 `upgrade_group` 叠加月卡和没有 `tokens.subscription_group` 的历史 API Key，解除、禁用或自然到期时按购买顺序恢复剩余有效权益，最终回退到原账号分组。
- `allow_wallet_overflow` 控制套餐耗尽后是否允许继续使用钱包；默认允许，以兼容旧数据。

### 额度通知

- 套餐总剩余额度达到或低于 2% 时发送“额度即将用尽”通知，内容包含当前剩余额度及订阅倍率到用户分组倍率的变化。
- 套餐全部额度耗尽且 API Key 实际回退时发送“额度已用尽”通知；同一额度周期、分组和通知阶段使用事件键去重。
- 通知任务持久化到数据库。发送失败后最多重试 5 次，间隔为 15 秒、1 分钟、5 分钟、15 分钟、30 分钟；服务重启后继续处理。
- 记录通知状态、渠道、尝试次数、下次重试时间、最终错误和发送时间，便于排查 SMTP 与配置问题。

## 主要模块与数据

| 模块/数据 | 作用 |
| --- | --- |
| `subscription_plans.subscription_group` | 套餐配置的权益分组 |
| `user_subscriptions.subscription_group` | 用户购买时的权益分组快照 |
| `tokens.subscription_group` | API Key 当前绑定的订阅权益 |
| `notification_deliveries` | 通知事件、发送状态和重试记录 |
| `model/subscription.go` | 套餐聚合额度、消耗、重置、失效与 Token 回退 |
| `service/billing_session.go`、`service/funding_source.go` | 订阅/钱包资金来源选择及分组限定扣费 |
| `middleware/auth.go` | 请求鉴权时校验订阅有效性并执行回退 |
| `service/quota.go` | 2% 和耗尽阶段判断、通知内容与事件去重 |
| `service/notification_delivery.go` | 持久化通知发送及重试任务 |
| `controller/token.go`、`service/group.go` | API Key 可选分组接口与绑定校验 |
| `controller/subscription.go` | 套餐启用状态变更、禁用时终止订阅及管理员绑定限制 |

数据库改动均为新增字段或新增表，通过 GORM 迁移兼容 SQLite、MySQL 和 PostgreSQL；新增字段为空时沿用旧的用户升级分组逻辑，不需要改写历史套餐。

## 问题与经验

- **订阅分组覆盖用户分组**：原方案直接修改用户唯一分组，多个套餐无法并存。应把“账号身份分组”和“套餐计费权益”拆开，并在 API Key 上保存权益绑定。
- **新增订阅分组后普通分组消失**：前端只使用了订阅分组列表。可选项必须由普通用户分组和有效订阅分组合并生成，不能互相替代。
- **购买两种月卡后只显示最近一个倍率**：权益查询不能把用户订阅状态压缩成单一当前分组。API Key 分组选项应枚举全部仍有可用额度的有效订阅，并按权益分组合并套餐标题和倍率。
- **套餐失效后旧 API Key 仍使用原倍率**：只在创建 Key 时校验不够。套餐失效、删除、到期和请求鉴权均需执行回退，并同步清除 Token 缓存。
- **禁用套餐与终止权益语义混用**：运行时不能持续使用 `subscription_plans.enabled` 判断已创建权益，否则待支付订单履约后会立刻失效。销售状态由套餐表控制，用户实际权益以 `user_subscriptions.status` 为准；禁用动作负责一次性终止当时已有订阅。
- **旧式叠加月卡回退错误**：仅判断“是否还有其他订阅”不足以恢复正确分组。应按购买时间选择最近的剩余权益，并沿购买时记录的前置分组链回退，避免恢复到已经失效的中间分组。
- **历史 API Key 缺少订阅绑定字段**：早期 Key 只有折扣 `group`，没有 `subscription_group`。失效处理需同时识别这类记录，否则旧 Key 会继续停留在已失效倍率。
- **手动把额度设为 100% 后没有耗尽邮件**：鉴权阶段先完成了 API Key 回退，后续请求已按钱包计费，绕过订阅结算通知。耗尽通知必须绑定“实际回退”事件，而不能只依赖订阅结算回调。
- **SMTP `connect failed: EOF`**：青云梯处于全局模式时会忽略 SMTP 的 `DIRECT` 规则。切换为规则模式后恢复；`198.18.x.x` 是 Fake-IP，不能单凭 DNS 判断，需从应用容器实际连接 SMTP 并确认收到服务器 `220` 响应。
- **邮件失败缺少证据**：只写运行日志无法追踪历史结果。通知任务应持久化状态和最后错误，并使用有限次数、递增间隔的重试，避免无限重发。

## 后续改动注意

- 套餐额度、API Key 回退和邮件通知是同一状态链路；修改任一处时应同时验证“鉴权 → 资金来源 → 扣费 → 回退 → 通知”。
- `subscription_plans.enabled` 是销售状态，`user_subscriptions.status` 是已发放权益状态。新增查询时不要重新用套餐启用状态过滤运行中的订阅。
- 禁用套餐属于不可逆的权益终止操作。后台确认框必须明确提示会终止现有订阅、回退 API Key，且重新启用不会自动恢复。
- 通知事件键必须包含用户、权益分组、通知阶段和额度周期，避免同周期重复邮件，同时保证套餐重置后可再次提醒。
- 回退前后的倍率应取请求实际订阅倍率和用户账号分组倍率，不要使用已失效套餐分组继续扣钱包。

## 部署注意

- “订阅权益分组”由前端提供，但生产前端会在 Go 编译时通过 `//go:embed web/dist` 写入可执行文件。非 Docker 部署拉取代码后，必须先重新构建 `web/dist`，再编译和替换 Go 二进制；只执行 `git pull` 或只重新编译后端可能继续提供旧页面。
- 非 Docker 构建顺序：

  ```bash
  cd web
  bun install --frozen-lockfile
  DISABLE_ESLINT_PLUGIN=true VITE_REACT_APP_VERSION=$(cat ../VERSION) bun run build
  cd ..
  go build -ldflags "-s -w -X 'github.com/QuantumNous/new-api/common.Version=$(cat VERSION)'" -o new-api
  ```

- 替换二进制后需重启实际运行的服务，并让浏览器强制刷新；若字段仍未出现，应先确认运行中的进程指向新二进制，而不是通过修改套餐或数据库配置规避。
