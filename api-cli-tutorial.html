中转站 API

这份教程使用当前站点的 OpenAI 兼容接口，带你从 API Key 配置开始，完成模型列表检查和第一条 Responses 请求。

开始调用 ↓ 选择操作系统
当前 Base URL
https://api.modelpass.work/v1
OpenAI 兼容 默认模型：gpt6-sol 需要 Bearer Key

开始前准备

只需要一把当前站点签发的 API Key，以及电脑上的终端。

01

创建 API Key

在站点控制台创建并复制可用密钥。示例中的密钥只使用占位符，不要把真实密钥提交到 Git。

02

确认模型权限

本教程默认使用 gpt6-sol。如果你的账户未开通该模型，请先在模型列表中选择可用模型。

03

准备终端

Windows 使用 PowerShell 或 CMD；Linux 使用 Bash；macOS 使用 Terminal 中的 zsh。

阅读代码块的方式：黄色高亮内容是你需要替换的值；蓝色高亮内容是可按需调整的默认值。复制按钮复制的是可直接执行的纯文本命令。

按操作系统调用

先执行“查看模型”确认 Key 和地址，再发送一条 Responses 请求。

PS

Windows · PowerShell

推荐给 Windows 10/11。变量只在当前 PowerShell 窗口生效。

1 · 设置 Key 并查看模型
# 把黄色内容替换成你的真实 API Key
$env:MODEL_PASS_API_KEY = "YOUR_API_KEY"
$env:MODEL_PASS_BASE_URL = "https://api.modelpass.work/v1"

curl.exe --fail-with-body `
  "$env:MODEL_PASS_BASE_URL/models" `
  -H "Authorization: Bearer $env:MODEL_PASS_API_KEY"
2 · 发送一条 Responses 请求
$body = @{
  model = "gpt6-sol"
  input = "YOUR_PROMPT"
} | ConvertTo-Json

Invoke-RestMethod `
  -Uri "$env:MODEL_PASS_BASE_URL/responses" `
  -Method Post `
  -Headers @{ Authorization = "Bearer $env:MODEL_PASS_API_KEY" } `
  -ContentType "application/json" `
  -Body $body
CMD

Windows · CMD

CMD 中使用 curl.exe，避免与 PowerShell 的命令别名混淆。

1 · 设置 Key 并查看模型
set "MODEL_PASS_API_KEY=YOUR_API_KEY"
set "MODEL_PASS_BASE_URL=https://api.modelpass.work/v1"

curl.exe --fail-with-body "%MODEL_PASS_BASE_URL%/models" ^
  -H "Authorization: Bearer %MODEL_PASS_API_KEY%"
2 · 发送一条 Responses 请求
curl.exe --fail-with-body "%MODEL_PASS_BASE_URL%/responses" ^
  -H "Authorization: Bearer %MODEL_PASS_API_KEY%" ^
  -H "Content-Type: application/json" ^
  -d "{\"model\":\"gpt6-sol\",\"input\":\"YOUR_PROMPT\"}"
$

接口与参数速查

这些示例使用站点的 OpenAI 兼容入口。

项目值 / 说明

Responses 接口POST /responses，完整地址为 https://api.modelpass.work/v1/responses。

常见问题

遇到报错时，优先检查地址、Key、模型 ID 和 JSON 格式。

返回 401 或 Unauthorized 怎么办？

确认 Key 是当前站点签发的 API Key，变量中没有多余空格或引号，并检查请求头是否为 Authorization: Bearer 你的Key。不要把控制台登录密码当作 API Key。

返回模型不存在或无权限怎么办？

先调用 /models 查看账户实际可用的模型 ID。模型名必须逐字匹配；如果列表中没有 gpt6-sol，请在命令里的蓝色模型值处替换成可用模型。

Windows 为什么要写 curl.exe？

PowerShell 里的 curl 可能是 Invoke-WebRequest 的别名。写成 curl.exe 可以明确调用系统自带的 cURL，避免参数行为不同。

如何让环境变量长期生效？

教程中的写法只对当前终端窗口生效。长期保存前请确认设备安全性：Linux/macOS 可写入 shell 配置文件，Windows 可使用系统环境变量设置；共享电脑不建议长期保存 API Key。

如何保护 API Key？

不要把 Key 放进公开仓库、截图、前端代码或聊天记录；怀疑泄露时立即在控制台撤销并重新创建。生产脚本优先从环境变量或密钥管理器读取。
